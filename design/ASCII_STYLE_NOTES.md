# glassbox 视觉方向：现代 ASCII art 风格笔记

> 2026-11-17。来源：用户对 5 张样稿的反馈、用户收藏的参考（Devault ASCII library、ascii.rest、Kailash/Hassan 的抖动背景、Inspora 的像素鲨鱼动画），以及一轮公开项目调研。
> 用途：后续样稿和定稿的设计约束。每条都应该能在页面上检查。

## 1. 一句话

现代 ASCII 风格是**在黑底上，用规整的发光格点（圆点 / 方块 / 盲文点）以亮度映射出会动的、有体积感的图形**。不是"用 `@#%` 拼图案"。

## 2. 用户对样稿的判断（定论）

| 样稿 | 保留 | 去掉 |
|---|---|---|
| A1 暗场 | 沉浸感，黑底上的动态主视觉 | 用 `@ # % +` 等字符拼图案，显得廉价 |
| A2 网点纸面 | 首屏 banner：动态格点背景 + 大标题，**标题周围有一圈留白（背景在标题处让开）** | 热力图、30 天统计用大圆球，难看 |
| C CRT | 整体氛围 | 全字符网格排版（字宽、全角对齐、留白配合差），没背景的人看不懂，容易两极分化 |
| D 玻璃 | 液态玻璃对动态背景的模糊 | 一堆圆角矩形卡片，AI 味太重，整体 pass |
| B 生成画 | 干净、安静、治愈 | — |

## 3. 观察到的视觉特征

### 3.1 单元（cell）
- 单元是**几何点**，不是字母：圆点（Round dots）、小方块（Bricks / Tiles）、盲文点阵（Braille，2×4 微点）、Bayer 抖动像素、明暗块（`░▒▓█`）。Devault 的风格分类：Classic、Detailed、Braille、Round dots、Dither、Bricks、Shade blocks、Gradient、Particle、Old monitor。
- **格点细而规整**：Devault 在一块约 500px 宽的画面里用 110×57 到 130×67 个单元。单元越小越"高级"，太大就脏。
- 亮度映射到点的**半径或明度**，而不是映射到不同字母。暗部留空，让黑底透出来。
- 用字符时也挑"点感"的字形（`· : ░ ▒ ▓`、盲文），避开 `@ # $ %`。

### 3.2 色彩与光
- 黑底（不是纯 #000，而是带一点冷或暖的近黑）。
- 单色或双色为主；彩色作品是**每个单元单独取色**（ascii.rest 的夜路、Devault 的粒子飞行器），而不是彩虹字符。
- 辉光只加在最亮的少数单元上做点缀（例如一盏车灯、一颗星），不是全屏泛光。调研结论：重辉光加彩虹色是"廉价"的标志之一。

### 3.3 动态
- **一定要动**，而且是慢的、连续的：噪声流场、3D 物体自旋或投影（donut 一族）、粒子拖尾、水波、视频转格点。
- 体积感来自**亮度渐变加透视**：一个在旋转的环面、一条往远处收拢的路、一束斜向冲出的光带。
- 可以响应鼠标（扰动、放大镜），离屏暂停，`prefers-reduced-motion` 时停在一帧。

### 3.4 和 UI / 排版的搭配
- 动态格点只占**首屏主视觉或背景的一块**，正文克制、留白大。
- 文字压在图上时，**背景在文字周围让出一圈空白**（A2 的做法，用户最喜欢）。
- 周边 UI 用"工程制图"语言：细线网格、交叉处 `+` 标记、等宽大写小标签（`02 STYLES`、`LIVE`）、方形小圆点、斜线阴影条、编号。**不用圆角卡片堆叠**。
- 正文字体：一款干净的无衬线（大标题可以很大、字距略紧），加一款等宽做标签和数字。

### 3.5 数据组件的格点化（glassbox 特有）
- 热力图、趋势、额度这些图也走格点语言，但要**细、小、整齐**：小方块或小圆点格子，用明度分级，不用大圆球。
- 参考 ascii.rest 的 data 分类（柱状图、仪表、sparkline、热力图、uptime bar）：等宽格子里放明暗块，单色，安静。
- 数据图表是"安静层"，首屏主视觉是"动态层"，两层不要抢。

## 4. 显得高级 vs 显得廉价

| 高级 | 廉价 |
|---|---|
| 格点细且规整，1–2 种颜色 | `@#%$` 拼图，字符偏大 |
| 慢、连续、有 3D 体积感，能响应鼠标 | 黑客帝国式字符雨，满屏乱闪 |
| 辉光只点在最亮处 | 全屏重辉光加彩虹色 |
| 图形和内容 / 数据有关 | 套模板，跟内容无关 |
| 动态区域有边界，正文留白大 | 满屏铺满，挤压正文 |
| 细线网格加编号标签的工程感 UI | 圆角磨砂卡片堆叠 |

## 5. 技术实现

- **WebGL fragment shader**（主流）：每个格子用 `fract(uv * grid)` 求局部坐标，再按采样亮度决定圆点半径或挑字形。能撑住 100×60 以上的格点在 60fps 下流动，适合首屏。
- **Canvas 2D**：适合低密度格点（几千个单元），开发简单，数据组件够用。
- **预渲染视频 / 帧**：最稳，但没有交互，也不能由数据驱动。
- glassbox 的主视觉要由数据驱动，所以选 shader 或 canvas，不选视频。

## 6. 参考清单

- Devault ASCII library / generator：devault.design/ascii-art-generator（风格分类、参数：cells、颜色、描边、辉光、扫描线）
- ascii.rest：MIT，236 个动画 piece，含 data 分类组件；彩色 piece 用 canvas 画格点
- play.core（play.ertdfgcvb.xyz）：文本格点 live-code 环境
- donut.c：3D 投影到字符亮度的经典
- Paper Shaders（shaders.paper.design）：dithering / halftone dots，PolyForm Shield 许可，引用前先确认许可是否合适
- pmndrs/postprocessing ASCIIEffect、three.js AsciiEffect（后者是 DOM 文本，性能差）
- Codrops 教程：ASCII Shader with OGL（2024-11）、Real-Time Dithering Shader（2025-06）、Shape-Aware ASCII Renderer（2026-09）
- Ghostty 官网首屏的 ASCII 幽灵动画；Nothing 的点阵（Glyph Matrix / Ndot）品牌语言

## 7. 后续反馈记录

- 2026-11-17 v2：圆点 vs 方块"区别不太大，可能方块更好一点" → 默认用**方块**单元。
- 2026-11-17：用户期望每轮都**逐版综合评价后修改**（A2 / C / B 各自按评价出 v2），而不是只合成一个新方向。D 已 pass，A1 的修改即 `v2-grid.html`。
- 2026-11-17 第三轮：**B-v2 特别好**（保留，只修瑕疵）；A1 pass；A2 与 C 都好，但不并行维护两版 → **把 A2 的优点融进 C**（C-v3）。
- **标题留白要窄**：像 B-v2 那样只让出一条细边，背景的流动能贴着字形透出来；A2/v2 那种宽描边太厚。
- **以数据为中心，少写解说小字**（用户指出这是 AI 通病）：每块只保留「标签 + 数据 + 单位」和真正有用的提示；去掉"越高越省钱""每一列是一天……"这类解释句、装饰性的开机日志。B-v2 首屏的画作说明属于作品本身，可以保留。
- 2026-11-17 第四轮：C-v3 和 B-v2「两个都非常好」→ 融合为 **C-v4**：以 C-v3 为基底（版式、细线分区、标题画进画布 + 字形细留白），换成 B-v2 的色调（墨底 #0f1218、纸色正文、石青 = Claude Code、雌黄 = Codex，去掉琥珀辉光、扫描线、暗角）和 B-v2 的「今日画作」首屏。
- 2026-11-17 C-v4 反馈「文字的点阵组成和光晕没有体现出来」→ 大标题改为与背景同一套格子的方块点阵 + 同色两层光晕；副标题字小，保持清晰矢量字加轻光晕；背景只有最亮的格子发光；91.2% 点阵数字和大数字加轻光晕。旧版存为 c-v4.pre-dotglow.html。
- 2026-11-17 用户问 C-v3 小字的质感：那是整页 CRT 扫描线蒙版（每 3px 一条 1px 暗线）+ 文字辉光 + 暗角，不是点阵。C-v4 已加回扫描线和暗角（强度调轻），`?scan=0` 可关掉对比。
- 2026-11-17 字体：宋体太弱，用户要「有重量、像日文明朝体、有力量感」→ 选思源宋体（Noto Serif SC，OFL）。用户要求**所有文字（含字母、数字）**统一用它：大标题 900 点阵，标题/大数字 700，正文 400，数字用 tabular-nums 对齐。默认即此（`?font=sans|serif|black|noto` 可切回对比）。定稿时改为自托管子集字体，不从 Google Fonts 在线加载（避免公开页访客 IP 外泄）。旧版 c-v4.pre-allserif.html。
- 2026-11-17 下方小字「亮度、大小、线粗不足，看不清」→ 衬线小字整体提亮（dim #8a877e→#aaa699，正文→#e4e0d4）、正文字重 500、各处小字放大约 1–1.5px，标签/仓库名/数值 600。
- 2026-11-17 画作说明行（今日画作 # / 占比 / 光点=Token）仍看不清 → 15px、600、提亮，并浮在扫描线之上（z-index）不被压暗。
- 2026-11-17 用户结论：衬线体不适合这种点阵/扫描线风格，回到**黑体 + 等宽**。默认 `font=sans`，可读性增强（提亮、加粗、放大）对黑体同样生效，全部文字都压在扫描线下。衬线版仍可用 `?font=noto900` 查看，旧版 c-v4.pre-sans.html。
- 2026-11-17 用户：「还是 C-v3 看着比较舒服」→ **C-v5 = C-v3 原样**，只换两样：B-v2 的色调（琥珀 → 墨底 / 纸色 / 石青 Claude / 雌黄 Codex，光晕、扫描线、暗角、滚动亮带、状态条全保留，只改颜色）和首屏的今日画作。字体、字号、标题实心字 + 光晕、版式都不动。唯一的版式改动：首屏说明行内容变长，手机上改为逐行排。C-v4 的点阵标题 / 衬线等试验到此为止。
- 2026-11-17 第六轮（用户把 c-v5 和参考站并排对比）：「对方一进去每个元素很明了、干净、信息量大又不乱；我的看似东西多，其实都是无用信息」。用户要求把今日画作放到页面最下面、向上扩散，变成背景。
  - 诊断：c-v5 首屏 550px 只讲了一句话，费用还和下方的 KPI 重复；光晕、扫描线、暗角、滚动亮带、状态条、点阵数字叠在一起降低了清晰度；字号层级太多。
  - 结论：干净与否不取决于深色还是浅色，取决于「一块面板 = 一件事」、统一的字号层级、每个数字带一行有用的补充（如 ↓输入 ↑输出、对比 7 日均）。
  - C-v6（`design/mockups/c-v6.html`）：画作改为 fixed 在视口底部、向上渐隐的背景层；正文改为直角细线半透明面板（带轻模糊）；三级字号统一为标签 13、数值 28 等宽、补充行 12 等宽；首屏直接是 5 个 KPI，然后是额度、整行宽的热力图、趋势加构成（Token 与按模型）、活动。扫描线、暗角、光晕默认关闭，`?fx=crt` 可加回对比。
- 2026-11-17 用户：「可以不用这么深的颜色吗，同是深色，淡一点的深色可能有高级感」。c-v6 加了三档底色，`?theme=ink`（原 #0f1218）、`graphite`（#1d2129，现默认）、`slate`（#272c35），截图在 `shots/c-v6-{ink,graphite,slate}-full.png`。等用户定档。
- 2026-11-17 用户定底色：**slate**（#272c35），c-v6 默认改为 slate。
- 2026-11-17 S09：C-v7（`design/mockups/c-v7.html`）= C-v6（slate）+ 机器（每台：代号、角色、系统、在线状态、CPU/内存/磁盘条、24h CPU 格点、探针状态）、服务（一个服务一行：状态、24h 在线率、CPU、内存）、Agent 运行时、定时任务、tailnet；"GitHub 贡献"改名为"提交"（含 GitHub、Gitea、本地）。直接读 glassbox.page/1；`?view=public` 显示公开快照的模糊占位。截图 `shots/c-v7-{private,public}-full.png`、`c-v7-mobile.png`。
- 2026-11-17 用户："背景暗一点，每个组件保持这个颜色"。slate 改为底色 #1b1f26，面板固定为旧版视觉色 #2d333d（rgba(45,51,61,.94)，几乎不透明）；旧版保留为 `?theme=slate0`，截图 `shots/c-v7-slate0-full.png`。
