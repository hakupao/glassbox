# 参考项目页面清单：svc-dashboard（Mikata）

> 用途：glassbox 设计参考。统计 https://svc.iamcheyan.com 公开快照包含的元素与功能。
> 采集日期：2026-11-17。方法：Playwright 桌面 1440×900 与手机 390×844 逐页签、逐子页截图，对照源码 `static/index.html` / `static/app.js`。
> 标记：🌐 公开快照可见 · 🔒 仅私有在线版有（快照里显示"请看在线版"或被隐藏） · ✏️ 写操作（快照里禁用）

## 0. 全局框架

| 元素 | 说明 |
|---|---|
| 顶栏品牌 | Logo + 名称 "Mikata" + 主机名 "debian" + 在线绿点 |
| 只读徽标 | "🔒 只读快照 ↗ 在线版"，点击跳私有实时版 |
| 主导航 | 桌面：右上胶囊按钮；手机：底部毛玻璃 Tab 栏（带图标）。共 5 页：概览 / 活动 / Agent / 用量 / 服务 |
| 语言切换 | AUTO / 中文 / English / 日本語（按 Accept-Language 自动） |
| 深链 | `#cat=xxx&atab=yyy`，每个页签和子页都可以被书签和分享 |
| 手机手势 | 下拉刷新、左右滑动切页、触感反馈、safe-area |
| 全局弹层 | 通用对话框、toast 通知、底部抽屉（Agent 详情 / VM 详情 / Tmux 终端）、全屏轨迹详情页 |
| 主题 | 浅色为主，卡片式布局，数字用等宽字体 |

## 1. 概览（首页）🌐

从上到下：

1. **今日用量 KPI 条**（5 个大数字）：总请求数（成功率）· 预估总费用 · 总消耗 Token（输入/输出/推理拆分）· 缓存命中率 · 平均首字延迟。右上"更多"跳到用量页
2. **GitHub 贡献热力图**：过去一年总贡献数，按周的方块矩阵，带图例，右上链接到 GitHub 主页
3. **系统状态 5 卡**：负载（1/5/15 分钟）· CPU（使用率 · 核数）· 内存 · 磁盘（超阈值变黄）· 运行时长
4. **负载 / CPU 趋势折线**：CPU / 内存 / swap / 负载 4 条线，24 个点。历史由发布器自己存，不依赖访客浏览器
5. **虚拟机卡（PVE）**：每台 VM 一张卡，显示状态、节点、CPU、内存条、磁盘、IP（IP 已打码），可展开详情抽屉
6. **四个入口卡**（2×2 网格），每张都有标题、计数和"查看全部 →"：
   - 活动：最近 4 条提交（仓库标签 · 作者 · 相对时间 · 提交信息）
   - Tmux：会话列表（名字 · 窗口数 · Agent/detached 标签）
   - 服务：端口小磁贴（运行中 / 总端口数）
   - Agent：每个 Agent 的额度进度条（5 小时 / 周额度、重置时间、百分比，颜色随余量变化）

## 2. 活动 🌐

页头："活动流：本地提交与 GitHub 动态合并时间线"。子页签有 3 个：

### 2.1 活动记录
- 过滤 chips（带计数）：全部 · Git 提交 · 含图片 · 已同步 GitHub · 本地未推 · Goal 完成 · Watchdog · 展开自动发布记录（自动发布的提交默认折叠，只留最新一条）
- 按天分组的时间线："2026-11-17 · 今天（3 次变更）"
- 每条事件卡：仓库彩色标签 · 分支 · 短哈希 · 状态标签（本地未推 / GitHub）· 标题 · 作者头像 · 绝对时间 + 相对时间 · 变更文件列表（M/A/D 标记，可"加载更多"）· "GitHub Diff ↗" 按钮

### 2.2 我的 PR
- 说明：向别人仓库提交的 PR，每 5 分钟同步，按审核、CI、冲突归类
- 搜索框 + 仓库下拉
- 状态 chips：进行中 · 需我处理 · 等待审核 · 可合并 · 草稿 · 已合并 · 已关闭 · 全部
- PR 卡：仓库#编号 · 日期 · 标题 ↗ · 审核状态 · CI 结果 · 是否冲突（标红）· +/− 行数 · 评论数

### 2.3 任务（事项清单与终端）
- 二级切换：`<仓库> 事项`（GitHub Issues 当任务队列）/ Tmux 终端
- 左右双栏：左边是列表（未关闭 / 已关闭 / 全部；每行有状态灯、标题、两行摘要），右边是详情
- 公开版只显示标题和摘要 🔒，正文、评论和终端都要去在线版看
- 在线版另有 ✏️：新建任务、派发给 Agent、停止、恢复、回信；阶段条；会话终端；执行时间线（对接 TaskHub 引擎，对话在 Telegram 里进行）

## 3. Agent（智能体中枢）🌐

页头"运行时、进程活跃度、实时路由与模型检测"，右上有刷新按钮。子页签有 3 个：

### 3.1 实时路由（Magpie 网关）
- 路由拓扑图：客户端 → 网关(127.0.0.1:3425) → 多个上游候选（账号 · 模型 · 余量条 · 重置时间），当前命中的上游加粗框出
- 路由策略文字说明（按余量和重置时间排序的规则）
- 统计：请求数 · 改道次数 · Agent 收到的错误数
- "最近一个请求是怎么路由的"：完整候选链 + 每个候选被跳过的原因
- 账号打码开关

### 3.2 供应商与模型
- 供应商列表：图标 · 名称 · 登录状态（账号已打码）· 模型数 · 能力图标 · 套餐（ChatGPT Plus / Free / SuperGrok 等）；未登录的灰显

### 3.3 运行时与环境
- KPI 5 卡：已安装（12/13）· 活跃进程 · 活跃会话 · 模型网关数 · 额度预警数
- 低额度预警横幅（红色）
- 过滤 chips：全部 · 运行中 · 有会话 · 有额度 · 未安装
- 每个 Agent 一个区块：名称 · 运行中(N) · 版本号 · 进程表（PID · CPU · 内存）· 会话列表（已打码）· "详情"按钮打开抽屉
- 底部还有模型 / API 区和环境区
- 涉及的 Agent：Oh My Pi、Hermes、Codex CLI、Antigravity(Gemini)、Claude Code、Grok、Cursor Agent、OpenCode、Copilot CLI、Kiro、Pi、MiMo 等
- ✏️ 在线版：一键安装/卸载 Agent、刷新额度、1-token 测模型

## 4. 用量 🌐

页头"消费趋势、请求统计与 Magpie 用量明细"。子页签有 2 个：

### 4.1 消费
- 时间段：今日 · 近 7 天 · 近 30 天 · 全部，右侧显示更新时间
- KPI 5 卡（和首页同一组）
- 消费趋势折线（$ 按小时）
- 智能体消耗分布：每个 Agent 的请求数 · 费用 · token（输入/输出）· 首字延迟 · 占比条
- 模型调用与速率：每个模型的请求数 · 费用 · 供应商 · token · 速度（t/s）
- 上游账号与配额池（账号已隐藏）

### 4.2 用量（额度看板）
- 视图：概览 · 请求 · 会话 · 上下文；时间段：今天 / 24 小时 / 7 天 / 30 天 / 全部 / 自定义；自动刷新间隔；总花费
- 每个供应商一张额度卡（瀑布流布局）：多个时间窗口的剩余百分比（5 小时 / 7 天 / 月 / 积分 / 余额 $）· 重置时间 · **配速**（实际消耗比匀速快多少或慢多少）· **剩余额度走势燃尽图**（实线是实际，虚线是匀速）· 按当前速度预计何时用完 · 多账号可展开
- 工具条：走势周期、账号打码、已用/剩余切换

## 5. 服务 🌐（部分 🔒）

页头"查找服务、查看资源占用；管理、网络和日志各自独立"。子页签有 5 个：

| 子页 | 内容 |
|---|---|

- **Agent 操作轨迹**：每个仓库 14 天双行色块 + 13 类事件计数 + 500 条事件流 + 类别筛选（`#traj-view`，快照首页没有入口）
- **Goal 卡片**：上下文体积警示、API 重试检测、进度清单、复制 resume 命令、⚡唤醒推进
- **Tmux 终端抽屉**：实时画面、发送按键、新建或结束会话
- 健康快检、网络测速、AI 清理

## 7. 公开快照的脱敏策略（值得照抄的部分）

- 账号、邮箱、会话名、命令行、工作目录：模糊块或 `[账号已隐藏]`
- 内网 IP 改写成 127.0.0.1 或打码；IPv6 用 `****`
- 服务名显示为 "?"；Issue 只公开标题和摘要
- 密钥用约 25 类正则扫描，统一替换成 `******`
- 写操作按钮全部隐藏，实时类面板改成"请看在线版"的占位文案
- 每 10 分钟由 systemd timer 导出、脱敏、推到 gh-pages；内容没变就不推送

## 9. 采集 → 部署 → 显示 的链路（2026-11-17 读源码确认）

- **单机单进程**：`dashboard.py` → `svcdash/main.py` 起一个 Python 标准库的 `ThreadingHTTPServer`，监听 `0.0.0.0:80`，作为 systemd 用户服务运行（MemoryMax 512M、CPUQuota 40%）。
- **采集方式以"请求时现采"为主**：前端定时请求 `/api/sys`、`/api/repos`、`/api/runtimes`、`/api/tmux`、`/api/magpie/usage` 等约 40 个接口，handler 收到请求后当场调用对应模块（读 /proc、调 PVE API、跑 CLI 等），部分结果带缓存。
- **只有两个独立的定时任务**：
  - `svc-dashboard-activity.timer` 每 60 秒扫一次 git 仓库，提交事件写入缓存文件。
  - `svc-dashboard-static-publish.timer` 每 10 分钟发布一次公开快照。
- **私有视图**：就是这个在线服务本身，家里局域网或 tailnet 能直接访问。
- **公开快照**（`scripts/publish_static_snapshot.sh`）：
  1. 在进程内调用各采集模块，拿到一份完整快照；
  2. `privacy.py` 按字段脱敏，把账号、命令、路径等**替换成**「[账号已隐藏]」之类的标记或 `******`；
  3. 把数据作为 `BOOT_JSON` **内嵌进 HTML**，不另外发 JSON 文件；
  4. 嵌入前用约 25 类正则再扫一遍密钥；
  5. 发布脚本再用正则替换邮箱、内网 IP、挂载路径；
  6. 对整个目录算 sha256，和上次一样就不推；
  7. 在临时目录里 `git init`，生成一个只有一个提交的 gh-pages，然后 `push -f`。gh-pages 永远只有一个提交，历史里不会留下旧数据；
  8. 推送前还有一道隐私 hook，按 $USER、家目录名、git 身份逐字节检查。
- **模糊是替换后的占位文本再加样式**，源码注释明确写着「不做发布后模糊，CSS blur 在开发者工具里一键就能去掉，不能当隐私边界」，和 glassbox §10.6 的规则一致。
